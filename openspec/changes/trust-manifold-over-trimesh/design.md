## Context

`solid_node/test.py` keeps two caches per built STL (ADR-029, ADR-052): a
bounds half that needs no mesh engine and a Manifold half built at the first
faceted comparison. The bounds half was also made the watertight gate, so
that a bad mesh is reported by file name once rather than failing deep in
the boolean engine, and so that even a solid the broad phase culls out of
every pair is validated. Its verdict is trimesh's `is_volume`.

Three seed projects showed the gate refusing what the engine accepts:
snappy-reprap's OpenSCAD 2021.01 exports (edges shared by four faces at the
snap tabs), fender-bender's build123d exports (T-junctions between
tessellated faces), and openvmp's vendor STEP tessellations (degenerate and
unshared triangles; touching bodies merged into one mesh). `manifold3d`
builds every one of the OpenSCAD and build123d meshes with `NoError` and
matching volumes; it builds the openvmp pieces once the degenerate triangles
are gone, which the fusion export already does and the leaf export does not.
Because the gate runs on selection, it also refuses exact-kernel runs that
never read a mesh, which is how openvmp — all exact leaves — lost
`assertNoSolidInterference`.

## Goals / Non-Goals

**Goals:**

- The mesh engine judges its own input. A faceted comparison raises only when
  Manifold refuses the mesh, naming the file and the engine's status.
- Selection, the broad phase and the exact path never judge a mesh.
- Exact leaf artifacts are exported without degenerate triangles.

**Non-Goals:**

- Repairing meshes. Nothing is sewn, filled or hulled; a mesh the engine
  refuses is still refused, and the error says why.
- `StlNode`'s import-time `require_watertight` gate (ADR-054). It answers a
  different question — is this committed file a solid to build from — with
  an explicit opt-out, and its behaviour is not changed here.
- Per-node tessellation precision (deferred; `docs/warts.md` item 5).
- Changing the `pieces` manifest's `watertight` fact, which is descriptive.

## Decisions

**The engine's status is the verdict.** `_cached_manifold` builds the
Manifold as today and then reads `manifold.status()`. Anything but `NoError`
raises `ValueError` naming the STL and the status, followed by trimesh's
`is_watertight` so the message still says what a human would
look for. The failed Manifold is not cached, so a rebuilt file is judged
afresh. `_flexible_manifold` does the same, naming the node, replacing its
`is_watertight` check. Alternative considered: keep trimesh's gate but
relax it to `is_watertight` — rejected, trimesh calls the four-face edges
non-watertight too, and any trimesh predicate second-guesses the engine.

**The bounds half only reads bounds.** `_cached_local_bounds` drops the
`is_volume` check. Its docstring and the ADR-029 comment stop describing it
as validation. The consequence the original design wanted — an unusable mesh
is reported by name — still holds at the moment it matters, the first
faceted read; a solid never read faceted is never at fault.

**`write_stl` always drops degenerate triangles.** The keyword goes; both
callers get the behaviour. The removal is trimesh's `nondegenerate_faces`
followed by `remove_unreferenced_vertices`, exactly what the fusion path
did. Alternative considered: a per-node opt-in — rejected, no caller wants a
zero-area triangle in an artifact.

**No fallback, no repair.** When Manifold refuses a mesh the project must
repair or replace it; the framework will not hull, fill or sew. That keeps
"pixels are evidence" honest: a verdict is reached on the part as built.

## Risks / Trade-offs

- [A solid that used to be refused at selection is now refused at its first
  faceted comparison, later and only if compared] → the error still names
  the file and now says what the engine objected to; a suite that never
  compares the part faceted has nothing to complain about.
- [A mesh trimesh calls non-watertight may be accepted by Manifold with a
  different volume than trimesh's] → the verdict is the engine's on the
  engine's mesh, as it always was after the gate; the projects that found
  this compared the volumes and they matched.
- [Degenerate removal changes an exact leaf's artifact bytes] → the artifact
  is regenerated by the existing digest/mtime currency; nothing keyed on the
  old bytes survives a rebuild.
