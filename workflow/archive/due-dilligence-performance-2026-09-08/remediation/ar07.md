# AR-07 — Repeated non-rigid SCAD path churn

## Formal evidence and diagnosis

The preserved `current-candidate-v2-projects.json` capture found continuous
same-input replacement in all three Abacus and V8 runs: Abacus `Column.scad`
and its source record, and V8 `CylinderUnit`/`ValveMotion` SCAD and source
records, retained identical bytes and desired timestamps while their inode and
change time moved. Metamaquina2 stayed clean. A finite third Abacus diagnostic
repeated the same two-path churn, ruling out one-run settlement.

The affected classes are ordinary `AssemblyNode` subclasses. Before this
correction, `generate_scad` made generation reuse conditional on `self.rigid`;
every assembly has `rigid = False`, so each instance immediately published its
SCAD even when the canonical path and source/currency identity were shared.
Instance state can make intermediate assembly SCAD differ, and later instances
restore the same final bytes on every build. Compare-before-replace correctly
retained equal bytes at each individual call, but could not prevent the
intervening path oscillation.

The independent cache-currentness flaw was that `SourceGeneration` stored
every completed `(path, identity)` in a set. After A then B were published to
one path, the old A membership remained and incorrectly said A was the current
path state. [ar07-red.log](ar07-red.log) records both deterministic failures.

## Ratified correction

The pilot explicitly re-ratified the narrow phase-coalescing boundary on
2026-09-07. The coherent proposal, D4, build-pipeline delta, tasks 5.6–5.8,
and ratification record are planning commit
`2ca4b9f06835d1133b6ad00eceecdee6e29b714c`, exactly one commit ahead of base
`40a848d6f8939b3e0d69e45a11b514b4ebfa263f` before implementation restoration.

A broad `not self.flexible` cache gate is not safe. A non-flexible assembly may
contain binding/state-dependent descendants, so first-instance reuse could
change the historically published last-instance SCAD. The narrow
correctness-preserving proposal is:

- Every instance still executes `render()` and `as_scad()` and contributes its
  distinct in-memory composition. During an active assembly source phase,
  non-rigid, non-flexible SCAD publication retains only the latest immutable
  desired text/stamp/digest/fingerprint for each canonical artifact path.
  Flexible snapshot/SCAD publication remains immediate, and direct generation
  outside a phase remains immediate.
- A clean phase exit performs a fresh contributor checkpoint, flushes each
  final desired path through the existing atomic compare-before-replace and
  currency ordering, then performs another fresh checkpoint. A body or first
  checkpoint failure discards pending values; a flush failure propagates
  through existing assembly failure handling. The builder's assembly phase is
  already entirely under the F04 project lock, and source identity remains
  guarded by both F05 values and the pre/post fresh checks.
- Rigid reuse remains immediate, but its generation state becomes canonical
  path to *currently published* full source/currency identity. A legitimate
  A→B→A sequence therefore performs all three publications.

The implementation follows that boundary in two narrow seams:

- `SourcePhase` recognizes only the established `assembly` producer phase,
  retains one frozen final payload per distinct canonical non-rigid path in
  last-occurrence order, performs fresh `assembly pre-flush` and
  `assembly post-flush` checkpoints, and clears pending state on every exit.
  A flush snapshots and clears the ordered mapping before publication, so a
  failed write leaves any completed atomic replacement intact but cannot run a
  later queued request or retain it beyond the phase.
- `generate_scad` computes text, stamp, scoped digest, and fingerprint before
  enqueueing only a non-rigid/non-flexible value. Rigid, flexible, and
  non-assembly calls remain immediate. Successful publication—not enqueueing—
  emits the generated log and updates the generation's canonical-path-to-
  current-full-identity map. An incomplete identity invalidates that entry, so
  both A→B→A and A→unknown→A publish all required states.

Every instance still renders and assembles its own model before enqueueing.
The queue holds one final SCAD text payload per distinct non-rigid assembly
path, not one payload per occurrence. Its memory is proportional to the
distinct paths and final text sizes in that one assembly phase; it is neither
a globally byte-bounded cache nor retained across phases or generations.
