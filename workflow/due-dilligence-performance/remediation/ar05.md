## Finding and boundary

A reload whose initial source census found a known foreign contributor
missing correctly recorded the failure, released the project build lock, and
waited. `_watch_broadly()` retained the missing path in its exact event filter,
but subscribed only to the entry module's directory. For an entry at
`models/model.py` and contributor at `assets/shape.js`, no event from the
sibling directory could reach that filter, so repair waited forever.

The correction stays inside the ratified recovery boundary. Unknown Python
edits remain broadly relevant only below the entry module's original recovery
subtree. Additional observer subscriptions are transport for exact known
contributors; they do not make unrelated foreign or sibling-Python files
relevant.

## Correction

Recovery now constructs recursive observer subscriptions for the entry
directory and the nearest existing parent of every exact known source. It
orders candidate directories from shallow to deep and drops any subtree
already covered by an earlier recursive subscription. This handles both a
missing file and a missing parent without redundant nested watches.

The event filter separately retains the entry directory as the broad Python
area. An event wakes recovery only when it is the exact canonical path of a
known source, or it is an eligible Python source below that original area.
The observer start/stop lifecycle, build-lock boundary, error publication, and
source-changed outcome are unchanged.

The regression creates `assets/unrelated.js` and `assets/unrelated.py` after
the broader transport subscription is active and proves both leave the worker
waiting. Recreating only `assets/shape.js` ends the worker cleanly.
